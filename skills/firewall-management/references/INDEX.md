# Firewall Management — Vendor Index

One row per supported vendor. Each vendor directory holds its own `procedure.md` (the full step-by-step),
plus wire-level `endpoints.md`.

| Vendor / Platform | Directory | Scope | Notes |
|---|---|---|---|
| Palo Alto Networks PAN-OS / Panorama | `panos/` | Address-object CRUD, security-policy-rule CRUD (incl. Panorama pre-rulebase), and the commit step, via the PAN-OS REST API | Candidate-vs-running config model: every write lands in the candidate config until a commit is issued. NAT-rule REST path and the commit request's exact literal fields were not confirmed this pass — see `procedure.md` Known limitations. Commit itself requires the older XML API, not the REST API, per the vendor's own documented scope limit on the REST surface. |
| Fortinet FortiOS (FortiGate) | `fortios/` | Address-object, firewall-policy, and destination-NAT (VIP) CRUD via the FortiOS CLI | CLI-driven, not REST-driven — FortiOS's dedicated REST/CMDB API reference is gated behind a Fortinet developer-network login and wasn't independently verified from a public source this pass. Source NAT and address/VIP groups are out of scope this pass. |
| Cisco ASA | `cisco-asa/` | Network-object, extended-ACL (access-list + access-group), and static/auto-NAT CRUD, primarily via the ASA CLI | Targets ASA specifically, not FTD/FMC — FMC's REST API documentation wasn't reachable from a public source this pass and needs its own future research pass/reference file. ASA's own REST API was only confirmed for auth basics and one object example; see `endpoints.md`'s explicit "not confirmed" list before assuming a REST path exists for access-list or NAT operations. |
| Juniper SRX (Junos OS) | `juniper-srx/` | Address-book and address-set CRUD (zone-attached and global books), custom application and application-set CRUD, zone-pair and global security-policy CRUD, reordering and shadow detection, and the commit step, via the Junos CLI | CLI-driven, so no `endpoints.md`. Candidate-then-commit model; `commit confirmed` auto-rollback is the documented safeguard. NAT, policy deactivation, and the Junos REST interface are not covered. Per-model scale limits and HA chassis-cluster commit behavior were not verified. Separate from the `juniper-srx` entry under `vpn-tunnel-management` (different object model: that one covers IPsec tunnel objects only). |

Correction to shared concepts: adding Juniper SRX narrowed the `SKILL.md` claim that no listed vendor enforces a reference check on delete. SRX enforces at commit for an address still in an address set and for an address set still referenced by a policy; the other three vendors still show none. Check-before-delete remains this skill's own discipline.
