# Firewall Management — Vendor Index

One row per supported vendor. Each vendor directory holds its own `procedure.md` (the full step-by-step),
plus wire-level `endpoints.md`.

| Vendor / Platform | Directory | Scope | Notes |
|---|---|---|---|
| Palo Alto Networks PAN-OS / Panorama | `panos/` | Address-object CRUD, security-policy-rule CRUD (incl. Panorama pre-/post-rulebases), rule move, NAT rules (family names unverified), commit, and Panorama push to device groups, via the PAN-OS REST API plus the XML API for commit/push | Candidate-vs-running config model: every write lands in the candidate config until a commit is issued. Panorama device-group/template management and template pushes are not covered; NAT family names are unverified against vendor docs — see `procedure.md` Known limitations. Commit itself requires the older XML API, not the REST API, per the vendor's own documented scope limit on the REST surface. |
| Fortinet FortiOS (FortiGate) | `fortios/` | Address-object, firewall-policy, and destination-NAT (VIP) CRUD via the FortiOS CLI | CLI-driven, not REST-driven — FortiOS's dedicated REST/CMDB API reference is gated behind a Fortinet developer-network login and wasn't independently verified from a public source this pass. Source NAT and address/VIP groups are out of scope this pass. |
| Cisco ASA | `cisco-asa/` | Network-object, extended-ACL (access-list + access-group), and static/auto-NAT CRUD, primarily via the ASA CLI | Targets ASA specifically, not FTD/FMC — FMC's REST API documentation wasn't reachable from a public source this pass and needs its own future research pass/reference file. ASA's own REST API was only confirmed for auth basics and one object example; see `endpoints.md`'s explicit "not confirmed" list before assuming a REST path exists for access-list or NAT operations. |
| Juniper SRX (Junos OS) | `juniper-srx/` | Address-book and address-set CRUD (zone-attached and global books), custom application and application-set CRUD, zone-pair and global security-policy CRUD, reordering and shadow detection, and the commit step, via the Junos CLI | CLI-driven, so no `endpoints.md`. Candidate-then-commit model; `commit confirmed` auto-rollback is the documented safeguard. NAT, policy deactivation, and the Junos REST interface are not covered. Per-model scale limits and HA chassis-cluster commit behavior were not verified. Separate from the `juniper-srx` entry under `vpn-tunnel-management` (different object model: that one covers IPsec tunnel objects only). |
| Fortinet FortiManager | `fortimanager/` | Address-object and policy-rule CRUD in an ADOM's policy package, and the install/partial-install push to managed FortiGates, via the JSON-RPC API | Centrally staged: writes change FortiManager's database only until a package install. Mostly secondary-sourced (only partial install read on a vendor page); NAT, ADOM locking and task polling unverified. Different from `fortios/` (direct device CLI). |
| WatchGuard Firebox (WatchGuard Cloud) | `watchguard-firebox/` | Firewall-policy CRUD, enable/disable, read of aliases and policy groups, and the deployment push, via the Firebox Management API | Saved-then-deployed model; deploy limited to 50 devices per request. Alias writes, NAT and policy schema fields unverified. |
| AWS Network Firewall | `aws-network-firewall/` | Rule-group and firewall-policy CRUD, attaching rule groups to a policy, and sync-state verification, via the AWS API | No address objects or NAT rules; different model (rule groups referenced by policies). Optimistic-lock update tokens, fixed rule-group capacity, asynchronous per-AZ propagation. |
| Zscaler ZIA (cloud firewall) | `zscaler-zia/` | Firewall filtering rule list/read/create/update/delete, configuration activation and activation status, via the ZIA REST API | Saved-then-activated model; activation is tenant-wide and also publishes other pending changes. Rules only: no IP-group or service-object writes, no NAT control, URL filtering or DLP rules. Action/state vocabularies, update semantics and default placement unverified. Separate from `zscaler-zia` under `zero-trust-access-policy-management` (different object model: access policy versus network firewall rules). |

Delete reference checks: PAN-OS, FortiOS, Cisco ASA, FortiManager and WatchGuard have no documented platform check against deleting an in-use object or rule; Juniper SRX enforces some cases at commit, and AWS Network Firewall rejects deleting a rule group or policy still in use; Zscaler ZIA documents no such check on rule deletion. Check-before-delete remains the procedure's own step. AWS Network Firewall has no address-object or NAT-rule model. FortiManager and WatchGuard stage changes behind a separate push, and ZIA keeps writes staged until a tenant-wide activation. ZIA rules may carry inline addresses alongside object references.
