# Endpoint Wiring — PowerDNS Authoritative Server Zones API

Literal API calls behind each capability named in `procedure.md`. Base path:
`/api/v1/servers/{server_id}/zones` (confirmed verbatim in the source's own request examples — not
the un-versioned `/servers/...` path). Auth: `X-API-Key: <key>` header.

## Modify RRsets

Tool hint: `PATCH /api/v1/servers/{server_id}/zones/{zone_id}`.

Body:
```json
{
  "rrsets": [
    {
      "name": "test.example.org.",
      "type": "A",
      "ttl": 3600,
      "changetype": "REPLACE",
      "records": [{"content": "192.168.0.5", "disabled": false}]
    }
  ]
}
```

`changetype` — "Must be one of DELETE, EXTEND, PRUNE or REPLACE" (verbatim).
- `REPLACE`: full RRset overwrite; requires `ttl` and `records`.
- `DELETE`: `records` must be empty; `ttl` must not be included.
- `EXTEND`: "only a single record shall be present, and it will be added to the RRSet if not already
  present" (verbatim).
- `PRUNE`: "only a single record shall be present, and it will be deleted from the RRSet if present"
  (verbatim).

`write_unchanged` (EXTEND/PRUNE only): "specifies whether a database update should be performed even
if the operation does not change the RRSet" (verbatim).

Multiple RRset entries may be included in one `rrsets` array, each independently specifying its own
`name`/`type`/`changetype`.

Response: `204 No Content` on success.

Client-body restriction (verbatim): "notified_serial, serial MUST NOT be sent in client bodies."

## Create a Zone

Tool hint: `POST /api/v1/servers/{server_id}/zones`.

Verbatim example:
```
POST /api/v1/servers/localhost/zones HTTP/1.1
X-API-Key: secret
Content-Type: application/json

{"name": "example.org.", "kind": "Native", "masters": [],
"nameservers": ["ns1.example.org.", "ns2.example.org."]}
```
Response includes SOA and NS records auto-generated by the server. Setting `dnssec: true` at creation
"sets up DNSSEC signing based on the other flags, this includes running the equivalent of pdnsutil
zone secure and pdnsutil zone rectify (if api_rectify is set to true)" (verbatim).

## Retrieve a Zone

Tool hint: `GET /api/v1/servers/{server_id}/zones/{zone_id}`.

## Update Zone Metadata

Tool hint: `PUT /api/v1/servers/{server_id}/zones/{zone_id}`. Used to set `api_rectify` or other
zone-level metadata after creation, distinct from the RRset-modifying PATCH.

## Delete a Zone

Tool hint: `DELETE /api/v1/servers/{server_id}/zones/{zone_id}`.

## Rectify a Zone

Tool hint: `PUT /api/v1/servers/{server_id}/zones/{zone_id}/rectify`.

Verbatim: "Rectify the zone data. This does not take into account the API-RECTIFY metadata. Fails on
slave zones and zones that do not have DNSSEC."

Automatic rectification alternative (verbatim): "When creating or updating a zone, the 'api_rectify'
field of the Zone can be set to true to enable this behaviour." Also: "DNSSEC-enabled zones should be
rectified after changing the zone data. This can be done by the API automatically after a change when
the [ALLOW-DNSUPDATE-FROM, FORWARD-DNSUPDATE, NOTIFY-DNSUPDATE, SOA-EDIT-DNSUPDATE] metadata is set."

## Other zone operations (referenced, not detailed in `procedure.md`)

- `GET /api/v1/servers/{server_id}/zones/{zone_id}/export` — export zone data.
- `PUT /api/v1/servers/{server_id}/zones/{zone_id}/notify` — trigger a NOTIFY.
- `PUT /api/v1/servers/{server_id}/zones/{zone_id}/axfr-retrieve` — trigger an AXFR retrieve (slave
  zones).

## Error response shape (all endpoints)

```json
{
  "error": "string",
  "errors": ["string"]
}
```
