# NetClaw adaptation

This contribution extracts portable procedures from all **235 tracked NetClaw skill files** at
[`95bb17e27a6a`](https://github.com/automateyournetwork/netclaw/tree/95bb17e27a6a2538fcb0168d0b1d0ab5bbe34692).
It reorganizes supported operations by capability and grounds their behavior in platform documentation
or publisher implementation, with original prose and separate wiring references. It does not install
NetClaw, copy its runtime, or claim that every source tool is supported.

The change adds **112 capabilities**, updates **8 existing capabilities**, and adds
**182 platform-reference directories**. The complete repository catalog has
**148 capabilities**. A platform-reference directory is a capability/vendor pair, not a count
of distinct companies. Multiple source skills can map to one capability and one source can map to several.
The [README catalog](../README.md#-current-skills) is the supported entry point.

The [machine-readable manifest](netclaw-manifest.json) records the exact source paths, SHA-256 hashes,
dispositions, destinations, scope gaps, contribution file inventory, and counts. Citations in each
vendor procedure and binding file are the operational evidence; source-example links in the manifest
are supplementary and are not an exhaustive citation list.

## Scope and sourcing decisions

- Native vendor APIs, SDKs, CLIs, or documented GUI procedures replace unverified wrapper names where appropriate. Compatibility is tied to the version or publisher commit identified by each reference.
- NetClaw implementation is a primary source only for NetClaw-owned behavior, such as its telemetry receivers, renderers, federation state and retrieval server. It is not treated as vendor authority for an underlying Cisco, AWS, Microsoft, or other platform.
- Business severity thresholds, mandatory ticket/GAIT workflows, organization-specific approval chains, role inference, automatic architecture design and universal compliance scores were not transferred as platform facts.
- All five blocked source skills remain visible in the map: three Claroty sources, Webex user context, and desktop GUI inspection. The Claroty documentation was inaccessible; the Webex context contract could not be retrieved; the desktop skill delegates to an unpinned external runtime.
- Existing pyATS, notification, pull-request, F5 and related capabilities are reused only for their documented subsets. A link to existing content is not a new claim that its entire historical scope was reverified.
- Newly authored procedures use publisher sources. The retained F5 load-balancing mapping includes an existing publisher-hosted community-source caveat. Existing Webex notifications and pull-request lifecycle references are retained without fresh complete verification. The new Infoblox read procedure uses the official SDK; older secondary-mirror-derived DNS/IPAM/DHCP mutation references were not used as evidence or relabeled as newly verified.
- Unknown schemas, incomplete pagination, unsupported operations and publisher defects are marked beside the affected procedure or binding. No production integrations were executed during this documentation conversion.

## Shared router changes

Existing routers changed only for new platform pointers or shared-content corrections:

- `device-cli-execution` adds RADKit, Netmiko and Junos pointers with explicit transport/read-only boundaries.
- `network-state-collection` adds NAPALM getters and Linux iproute2 observations.
- `parallel-task-execution` adds Nornir read-only tasks and preserves host-keyed results instead of implying pyATS-style ordered return values across platforms.
- `vulnerability_lookup` restores a thin router and source-specific no-data, authentication and applicability semantics. An NVD key is not universally required; lookup success does not prove that a device is safe.
- `zero_trust_access_policy_management` corrects the false immediate-enforcement assumption: ZIA rule persistence and activation are separate stages. The vendor procedure includes activation and its tenant-wide pending-change implications.

New multi-platform routers were also checked as vendors were combined. In particular, controller
reads accept a publisher reference or live schema catalogue; a live catalogue is not universal.
Cloud queries retain each platform's actual scope rather than requiring account/region/time filters
that some providers do not expose. Retrieval treats returned text as evidence, not trusted instructions.

## Material publisher findings

These are documented in the affected references, not silently repaired by invented runtime behavior:

- Cisco openVuln's old host and OS-family routes are obsolete; the current specification has response-shape and pagination ambiguities. NVD request parameters were checked independently of its response schema.
- Vault KV v1/v2 routing and a destroyed/deleted latest version must not trigger an invented fallback read.
- NetClaw telemetry has timezone-filter and severity-filter defects, a placeholder SNMPv3 path, unmasked community data in a detail result, and IPFIX template-domain/expiry limitations.
- NetClaw routing-speaker mutations have fallback/argument defects; only verified existing-speaker reads were extracted. Its federation comparison helper is a placeholder.
- Forward MCP caching can reuse query pages, while batch mode omits some supplied options. Preview output is not a complete dataset. Batfish can create model state and is not universally read-only.
- The Infoblox SDK and several publisher examples disable TLS verification; procedures flag the unsafe behavior and require an appropriate verified transport. Sensitive output fields are identified where publisher APIs expose them.
- Three.js output naming can collide and its source-label interpolation is unescaped. Unreal render success can coexist with incomplete actors or errors. Artifact generation is kept separate from display or complete-scene verification.

## Verification

The conversion uses a bounded manual Ralph-style author/review loop, capped at 25 iterations. The
Claude-specific stop hook is not represented as running in Codex. The final PR states the completed
iteration count. Parallel agents researched independent platform groups and performed additional
scope and risk-focused reviews.

From a checkout containing this contribution:

```sh
python3 scripts/validate_netclaw_adaptation.py
```

For exact source coverage and content-hash verification, provide a local NetClaw checkout at the
pinned commit:

```sh
python3 scripts/validate_netclaw_adaptation.py --source /path/to/pinned/netclaw
```

The standard-library validator checks inventory uniqueness/counts, destinations, README coverage,
local links, required sections, frontmatter keys, router budgets, HTTP wiring placement and companion
naming. The optional source argument also checks the tracked source set and every source hash.
New routers additionally passed the skill-creator YAML/name/description validator. Router sizes were
measured with `wc`; whitespace was checked with `git diff --check`. Static checks do not validate
live credentials, tenant-specific schemas, execution effects or every semantic claim. The references
preserve these practical limits and require the documented execution prerequisites.
